# 데이터 연결 규칙

## 원본과 고정 ID

Zotero가 제목·저자·학술지·행사·날짜·태그의 기준 원본입니다. 홈페이지가 별도의 고정 ID를 관리합니다. 홈페이지 고정 ID는 `pub-0001`, `talk-0001` 같은 형태이고 최초 부여 후 바꾸지 않습니다. 최초 부여 순서는 표시용 순위가 아니며, 홈페이지 목록은 날짜 등으로 따로 정렬합니다.

현재 자료는 논문·자료 106개와 발표 158개입니다. 논문·자료에는 `journalArticle` 97개, `conferencePaper` 5개, `thesis` 1개, `dataset` 3개가 있습니다. 발표는 모두 `presentation`입니다. 출처의 항목 종류를 보존합니다.

| 구분 | 원본 필드 | 규칙 |
| --- | --- | --- |
| Zotero 연결 | `Key` | 입력 자료 이름(namespace)과 함께 식별. 바뀐 Key도 과거 연결 이력에 남김 |
| 제목 | `Title` | 과학 기호와 내용을 보존하고 HTML 태그는 표시 가능한 텍스트로 정리 |
| 저자 | `Author` | 원래 저자 순서 보존. 첫 저자를 실제 발표자로 단정하지 않음 |
| 날짜 | `Date`, `Publication Year` | 원래 일자 정밀도 보존. `2026-07`을 임의의 날짜로 변환하지 않음 |
| 논문 발행처 | `Publication Title` | 학술지·학회논문집 등 원래 값 사용 |
| 논문 상세 | `Volume`, `Issue`, `Pages` | 결측값·`null-null` 같은 표시 불가 값은 빈값으로 처리하고 보고서에 기록 |
| 발표 행사·장소 | `Meeting Name`, `Place` | 누락은 미기재로 취급 |
| 발표 유형 | `Type` | 원문을 보존. `Invited`만으로 `Oral`을 추가 추정하지 않음 |
| DOI | `DOI` | 접두 URL 제거 등으로 비교 형식을 통일. 서로 다른 비어 있지 않은 DOI의 변경은 확인 대상 |
| 웹 주소 | `Url` | http/https 링크만 사용 |
| 사용자 태그 | `Manual Tags` | 저자 역할과 사용자가 정한 연구주제 분류에 사용 |
| 자동 태그 | `Automatic Tags` | 원본 검색어로 보존. 저자 역할의 근거로 사용하지 않음 |

`Notes`, `Extra`, `File Attachments`, `Link Attachments`, 로컬 접근 경로와 Zotero 내부 관리 시각은 공개 데이터에 복사하지 않습니다. 별도 수상 정보 등이 필요한 경우 검토 후 홈페이지 콘텐츠에 직접 입력합니다.

## 갱신 시 연결 순서

1. 기존 namespace와 Key가 같으면 동일한 홈페이지 ID를 유지합니다.
2. Key가 새로 생겼지만 DOI가 기존 항목과 유일하게 일치하고, 종류가 맞으며, 같은 가져오기에서 기존 항목이 별도로 존재하지 않으면 재연결합니다. 이전 Key도 대응 이력에 남깁니다.
3. DOI 중복, 서로 충돌하는 연결, 기존 Key의 DOI 변경 등은 자동으로 덮어쓰지 않습니다. 같은 Key의 DOI를 의도적으로 수정한 경우에는 별도 해결 파일에서 기존 홈페이지 ID를 지정해 확인하고, 이전·새 DOI를 보고서에 남깁니다.
4. DOI가 없는 자료나 발표는 제목·행사·날짜·발표 유형을 확인 후보를 찾는 데 사용합니다. 후보가 있으면 사람이 연결을 지정해야 합니다.
5. 같은 제목의 구두발표와 포스터를 하나로 병합하지 않습니다. 비슷한 제목의 별개 항목은 해결 파일에서 `new`를 지정할 수 있습니다.
6. 새 CSV에 없어진 항목은 `source_missing`으로 표시하고 마지막 정보와 홈페이지 고정 ID를 보존합니다. 재등장하면 같은 ID를 사용합니다.
7. 하나라도 미해결 연결이 있으면 보고서만 갱신합니다. 기존 registry와 화면용 데이터는 그대로 유지합니다.

기존 화면용 데이터가 있는데 `registry.json`만 없어진 경우에는 ID를 새로 부여하지 않고 중단합니다. 보관한 registry를 복구한 뒤 계속합니다.

원본에서 사라진 항목을 실제 홈페이지에서 표시할지는 별도 공개 설정으로 정합니다. CSV에서 빠졌다는 사실만으로 해설·그림 파일을 삭제하지 않습니다.

## 추가 콘텐츠

`content/items.json`은 다음 구조입니다.

```json
{
  "schema_version": 1,
  "items": {
    "pub-0001": {
      "summary": "직접 작성한 해설",
      "image": "assets/publications/pub-0001.png",
      "image_alt": "그림의 설명",
      "links": [{"label": "관련 자료", "url": "https://example.org/"}],
      "person_ids": [],
      "featured": false,
      "hidden": false
    }
  }
}
```

위 예시는 입력 형식만 설명합니다. 원본 논문에 대한 실제 해설이 아닙니다. 추가 콘텐츠의 키는 Zotero Key가 아니라 홈페이지 ID입니다. 변환기는 이 파일을 수정하거나 삭제하지 않습니다. 이미지 파일도 별도로 보존합니다.

## 기존 태그

| 태그 | 표시 역할 |
| --- | --- |
| `BR:first` | 제1저자 |
| `BR:co-first` | 공동 제1저자 |
| `BR:corresponding` | 교신저자 |
| `BR:co-corresponding` | 공동 교신저자 |

여러 역할을 함께 표시할 수 있습니다. 태그가 없는 항목에는 역할을 추정해 채우지 않습니다. 수동 태그와 자동 태그는 구분해서 보존합니다.
